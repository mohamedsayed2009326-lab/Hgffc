# منظومة إدارة ومطابقة لوحات السيارات

مشروع React 18 + Vite + Capacitor، واجهة عربية RTL ومهيأ للتغليف كتطبيق Android بالمعرّف `com.plates.manager`.

## الموجود في النسخة الحالية
- واجهة موبايل RTL، شريط تنقل سفلي، تصميم كحلي وذهبي.
- على Android: تخزين أساسي في SQLite داخل مساحة التطبيق الخاصة، مع فصل القاعدة الأولى والثانية. في معاينة الويب: IndexedDB. يتم ترحيل بيانات IndexedDB القديمة إلى SQLite عند أول تشغيل على Android إذا كانت قاعدة SQLite فارغة.
- رفع Excel/CSV وإضافة بيانات مع الاحتفاظ بتكرارات اللوحة كمرات رصد.
- توحيد الأرقام العربية/الفارسية وبعض الحروف العربية، والبحث والتصفية وتقسيم السجلات إلى صفحات.
- مطابقة النص الملصوق مع القاعدة الأولى أو الثانية أو الاثنتين، وعرض مرات الرصد وتصدير تقرير Excel.
- تصدير سجلات Excel ونسخ JSON احتياطية، واستعادة JSON، ومسح القاعدة بتأكيد. استبدال القاعدة على Android يتم داخل معاملة SQLite واحدة؛ لو فشلت المعاملة تُلغى بدل ترك قاعدة نصف مكتوبة.
- سجل عمليات محلي ورسوم إحصائية.
- GitHub Actions يبني APK تجريبيًا ويرفعه كـ Artifact، وينشره في Releases عند دفع tag يبدأ بـ `v`.

## تشغيل نسخة الويب محليًا
يتطلب Node.js 20 أو أحدث:

```bash
npm install
npm run dev
```

## بناء Android
يتطلب Android Studio / Android SDK وJDK 17:

```bash
npm install
npm run build
npx cap add android
npx cap sync android
npx cap open android
```

ومن مجلد `android` شغّل `./gradlew assembleDebug` لبناء APK تجريبي.

## GitHub Actions
ارفع ملفات المشروع إلى مستودع GitHub، ثم افتح تبويب Actions وشغّل `Build Android APK` يدويًا. يمكن أيضًا دفع tag مثل `v1.0.0` لنشر Release. النسخة التي يبنيها الملف حاليًا هي **Debug APK غير موقّع بمفتاح إصدار ثابت**؛ تصلح للاختبار، وليست إعداد توقيع إنتاج نهائي.

## التوقيع والتحديثات
لإصدار APK يمكن تحديثه فوق نسخة منشورة سابقًا، يجب إنشاء keystore خاص بك والاحتفاظ به بأمان، ثم إعداد أسرار GitHub واستخدامه في خطوة `signingConfig`/`apksigner`. لا تضع ملف keystore أو كلمة مروره داخل المستودع. لا يمكن ضمان التحديث فوق نسخة قديمة إذا اختلف مفتاح التوقيع.

## حدود مهمة قبل الاستخدام الفعلي
هذه نسخة أولية عملية وليست تنفيذًا كاملًا لكل بند في المواصفات. تحديدًا: استخراج روابط HYPERLINK من جميع صيغ Excel، التعرف المتقدم على الأعمدة/الشركة/VIN/الملاحظات، سياق 4 لوحات قبل وبعد آخر ظهور، والتوقيع الثابت للإصدارات تحتاج استكمالًا واختبارات على أجهزة فعلية. استيراد الملف حاليًا يعتمد على أسماء أعمدة شائعة، ولا ينبغي اعتماد النتائج التشغيلية قبل اختبارها بملفاتك الحقيقية.

## التخزين والخصوصية
على APK، السجلات تُحفظ في SQLite داخل مساحة التطبيق الخاصة ولا تحتاج إلى إنترنت أو خادم، وتبقى عادةً بعد إغلاق التطبيق وإعادة تشغيل الهاتف. في الويب تستخدم النسخة IndexedDB. حذف التطبيق أو مسح بياناته أو تعطل الجهاز قد يؤدي إلى فقد البيانات؛ لذلك صدّر نسخة JSON دوريًا واحفظها خارج التطبيق. تفعيل Android Backup ليس بديلًا عن النسخة الاحتياطية المستقلة. تم حذف تحميل خطوط Google الخارجي للحفاظ على التشغيل دون إنترنت؛ الواجهة تستخدم خطوط Cairo وIBM Plex Sans Arabic إن كانت مثبتة على الجهاز ثم خطوطًا بديلة. للحصول على تطابق بصري مضمون، أضف ملفات الخطوط محليًا إلى المشروع.


## اختيارات تقنية لتقليل الحجم وحماية البيانات

- احتفظنا بـ React لأنه مسؤول عن واجهة التطبيق التفاعلية، وبـ Vite لأنه يبني ملفات الواجهة؛ لا يعمل Vite كخدمة داخل APK.
- احتفظنا بـ Capacitor لتغليف التطبيق وربط ميزات أندرويد.
- أزلنا `recharts` واستبدلنا الرسوم بمخططات CSS بسيطة لتقليل اعتماديات وحجم الواجهة.
- أبقينا `xlsx` لأنه ضروري لقراءة وكتابة Excel، و`lucide-react` للأيقونات، و`@capacitor-community/sqlite` للحفظ المحلي في APK، و`idb` لتشغيل معاينة الويب.
- أضيفت علامة ترحيل دائمة داخل SQLite حتى لا يعيد التطبيق استيراد بيانات IndexedDB القديمة بعد أن يمسح المستخدم القاعدة عمدًا.
- تم إصلاح عدّاد اللوحات في القاعدتين ليقرأ العدد الفعلي لكل قاعدة، وإيقاف تقرير الاستيراد الناجح إذا فشل الحفظ.

## ملاحظات البناء والتوقيع

تشغيل GitHub Actions بدون إعداد أسرار التوقيع ينتج APK تجريبيًا (Debug) فقط، ولا ينبغي اعتباره إصدار تحديث دائم. لإصدار تحديثات فوق نفس التطبيق، أنشئ keystore واحدًا واحتفظ به بأمان، ثم اضبط أسرار GitHub التالية: `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. فقدان keystore يعني أنك لن تستطيع توقيع تحديث مطابق للنسخة الموقعة به.
